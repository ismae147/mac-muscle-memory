Hold a key. Pick the accent. Keep typing.

accentpop brings macOS press-and-hold accents to Linux. Hold a letter for 300 ms and a numbered picker opens at your text caret with ñ, é, ü, ¿ and the rest. No layout switching, no Compose sequences.

Appears where you type

The popup anchors at the text caret reported by IBus or AT-SPI. If there is no room below the line, it flips above.

Shortcuts stay shortcuts

Holding a key together with Ctrl, Alt or Super never opens the picker.

Works with IBus apps, including Flatpak

Characters are injected through persistent spare keycodes, so asynchronous input paths do not drop them.

Reversible

Autorepeat is turned off for the 18 trigger keys only, and restored with the keycodes when the service stops.

Eighteen keys, one hold away.

Every trigger and its variants, in the order the popup shows them. Spanish, French, German, Portuguese, Polish, Czech, Turkish and Nordic letters are covered.

Hold Shift for the uppercase set. Shift+s gives Ś Š, since ß has no single-character capital. The popup shows at most nine variants.

Works where you type.

X11 does not expose the text caret, only the focused app knows it. accentpop listens to the sources apps already use, and picks the freshest one.

IBus

Caret rectangle

Chromium, Chrome, Electron and Qt WebEngine apps, browsers, and their Flatpak builds.

Apps report their caret so IBus can place its candidate window. accentpop reads that geometry and never answers.

AT-SPI

Character extents

GTK apps and terminals, plus other toolkits that expose text accessibility.

Only events from the process that owns the active window are trusted.

Fallback

Click, then pointer

Apps that report no caret at all.

The popup opens at your last left click, since people click where they are about to type. Otherwise, at the mouse pointer.

It watches keys. It is built to know almost nothing.

Press-and-hold needs to observe the keyboard. Here is exactly what goes in, and what never does.

Declaration of contents

accentpop.py
What accentpop reads and does not read
ItemDeclared
Key codes, matched against 18 trigger keysYes
Caret geometry, a rectangle on screenYes
The text of any fieldNever
Anything written to diskNever
What you type, in logsNever
Network accessNone

It talks only to the local X server, the IBus bus and the AT-SPI bus. AT-SPI can read field text; accentpop only asks it for character extents.

No root

Nothing needs sudo. Dependencies live in a per-user venv at ~/.local/share/accentpop.

No system packages

Installing never touches apt. It uses the PyGObject GNOME already ships.

Reversible

Stopping the service restores autorepeat and the keycodes it borrowed. Uninstalling is three commands.

One file to audit

The daemon is a single Python file, accentpop.py. The injection and logging paths are short on purpose.

Where it delivers.

Tested on Zorin OS 18 (Ubuntu-based) with GNOME Shell 46. Other GNOME on X11 systems are likely to work, and reports are welcome.

Delivered

X11

GNOME on Xorg, with IBus recommended for the best caret placement. It works without IBus too.

  • python3 and PyGObject with GTK 3, preinstalled on GNOME
  • Coexists with evdev remappers such as keyd
  • The popup follows your light or dark preference
Return to
sender

Wayland

Not supported yet. accentpop relies on the X11 RECORD and XTEST extensions, which have no Wayland equivalent. The installer refuses to run in a Wayland session.

On GNOME, pick GNOME on Xorg from the gear menu on the login screen.

Questions.

Why not just set a Compose key?

If you only need ñ and the five accented vowels, a Compose key is lighter and needs no daemon:

gsettings set org.gnome.desktop.input-sources xkb-options "['compose:ralt']"

accentpop is worth it when you want the full variant sets, or the macOS muscle memory you already have.

Can it see what I type?

It sees every keystroke, because press-and-hold is impossible otherwise. It only compares key codes against the 18 triggers, writes nothing to disk, logs status messages only, and has no network access. The caret sources are used for geometry, never text.

Does holding a key still repeat it?

Not for the 18 trigger keys. Holding a no longer types aaaa, the same as on macOS. Every other key repeats normally, and autorepeat comes back when the service stops.

Will it work on Wayland?

Not yet. The key observation and injection rely on XRecord and XTEST, which Wayland does not provide. Use the Xorg session from the login screen's gear menu.

Where does the popup show up in apps with no caret?

At your last left click, then at the mouse pointer. Click in the text field first and the popup anchors there. Caret reports older than 15 seconds are ignored.

How do I uninstall it? 
systemctl --user disable --now accentpop
rm -rf ~/.local/share/accentpop ~/.config/systemd/user/accentpop.service
systemctl --user daemon-reload

Stopping the service already restores autorepeat and the keycodes it used. Then delete the cloned folder.

Does it work on my distro?

It is tested on Zorin OS 18 with GNOME Shell 46. Other GNOME on X11 systems are likely to work. A compatibility report on GitHub issues helps everyone.
